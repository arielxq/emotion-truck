專題企劃書：情緒垃圾車 Emotion Garbage Truck

用搖桿選擇情緒，交給一台有脾氣的垃圾車。

版本：2026-10 現行規格

類型：ESP32 互動裝置／Web Showcase／資料統計

一句話：使用者把難以消化的情緒交給垃圾車，透過聲音、表情與狀態轉換，完成一段可操作、可觀察的象徵性清運流程。

能力邊界：本裝置不是心理治療工具，也不提供醫療建議。

一、專題目標

以 ESP32、搖桿、LCD、LED 與蜂鳴器建立實體互動；以 Web Showcase 提供不接硬體時的展示與測試；以 FastAPI/SQL 保存模擬事件並呈現情緒與清運統計。

二、現行硬體

元件接點用途
ESP32 DevKit—狀態機與輸入輸出控制
HW504 搖桿VRx GPIO34、VRy GPIO35、SW GPIO32情緒選擇、旋轉與確認
LCD1602 I2CSDA GPIO21、SCL GPIO22、通常為 0x27狀態文字與表情
單色 LEDGPIO27 經 220Ω狀態閃爍提示
無源蜂鳴器GPIO25原硬體音效與 Fur Elise

三、13-state 流程

REST_CLOSED → IDLE → ACCUMULATING → FULL → APPROACHING
→ ARRIVED → THROW_READY → THROWING
→ RESPONDING_CAREFUL / RESPONDING_THANKS / RESPONDING_RECYCLE
→ COLLECTED → IDLE 或 REST_DAILY_LIMIT
狀態規則輸入
REST_CLOSED休息，保留 bags無效
IDLE / ACCUMULATING同方向完成 3 次 push，再按 SW 確認後 bags +1；上限 5上／左／右選擇，下取消
FULLbags=5，等待垃圾車無效
APPROACHING播放約 10 秒 Fur Elise 後抵達無效
ARRIVED以 atan2 累積 360°、720°、1080°旋轉三圈
THROW_READY / THROWING按 SW 後進入不可取消清運A 確認
RESPONDING_*CAREFUL 50%、THANKS 25%、RECYCLE 25%無效
COLLECTEDdaily count +1，保留剩餘 bags無效
REST_DAILY_LIMIT每日清運達 2 次reset day

bags 結算：CAREFUL／THANKS 將 bags 歸零；RECYCLE 在原有 N > 0 時隨機保留 1～N 包（也可能全數保留），原有 0 包維持 0。收走數量 = N − 保留量。COLLECTED 不再改 bags；每日第 2 次後休息，reset day 保留 bags；完整重設才歸零。

四、聲音與視覺

  • 瀏覽器 Web Audio 優先重現 `platformio/src/sounds.h` 與 `sounds/` 的頻率、節奏與時長。
  • APPROACHING 與 COLLECTED 各播放約 10 秒 Fur Elise。韌體以 duty 控制整段漸強／漸弱；Web 接近段為固定音量，離開段為逐音符淡出。
  • 單色 LED 依狀態熄滅、短閃、快閃、慢閃、長亮或雙短閃。
  • 瀏覽器需先按「啟用硬體音效」；音效不可用時，狀態機仍可操作。

五、Web Showcase 與後端

truck/showcase.html Section 10 提供固定尺寸 LCD、搖桿／SW、流程測試控制、bags／每日次數與 Web Audio；Section 10b 提供 Chart.js 示範圖表、今日狀態卡、操作說明與 API 預留端點。showcase 目前不即時呼叫 FastAPI；後端 API／SQL 可獨立測試。

Wokwi 為外部硬體展示：開啟 Wokwi 專案。目前 showcase、ESP32 與 Wokwi 不作雙向即時同步。

六、資料與驗證

後端模擬 API 使用 `SIM-001` 與 `source=SIMULATION`；showcase 目前只展示前端示範資料。SQL 的 `returned_bags` 是歷史相容欄位，語意為收走數量。硬體實機與 Web 測試分開記錄，Web 流程完成不代表 ESP32 已通過實機驗證。
